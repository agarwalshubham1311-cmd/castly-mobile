# Phase 5 implementation and review

Issue #6 is the authoritative scope; this branch starts at `b86deb4fac8c44ac28ac2a93d97b38c4ad1c6032` without Phase 4. M5.1 adds creator-consented broad region and day declarations, combined published/eligible talent filters, stable sorts and bounded pagination. A date is `confirmed` only when every requested day was explicitly declared available and no accepted booking conflicts; missing days are `unknown`, and a conflict on a creator-declared day or explicit unavailability is `unavailable`. The creator can withdraw a declaration, returning that day to `unknown` even if it has a private accepted booking. A client who explicitly includes unknown dates must still confirm availability directly; unknown is never date-fit evidence. This keeps booked and unbooked undeclared dates indistinguishable to the searcher. No booking IDs, counts or private booked-day calendar are returned.

M5.2 and M5.3 use a local taxonomy parser, explicit confirmation of each inferred constraint, and deterministic ranking. Required skills, category, city/opt-in region, an indicative INR per-day ceiling, and confirmed date availability (unless the client explicitly includes unknown) are hard filters. A campaign-total budget remains an unverified final quote, not a derived day-rate cap. Candidates are ordered by the full deterministic score before the 50-row working limit, including preferred-skill overlap, rate fit, creator-declared days and a boolean from a relevant public portfolio label. The shortlist is capped at 20. Score explanations reference only these source facts; portfolio labels are creator supplied, and format/audience suitability remains unknown. No popularity, subscription tier, Phase 4 trust, private purchases, protected attribute or review score influences ranking. Personalization and external processing are distinct opt-ins. The only configured provider is disabled, so every current recommendation is labeled deterministic, including when the recommendations rollout gate is on.

The provider interface accepts only pseudonymous numeric/boolean signals. A two-worker, eight-waiting-task wrapper bounds a provider attempt to 250 ms, validates a permutation, falls back after timeout/throw/malformed output, and stores only short-lived orders for at most 256 actor-scoped entries. Source candidate facts are queried again after a provider wait and on cache hits; a changed/unpublished creator invalidates the response. Withdrawal invalidates the actor cache and pending insertion. No raw prompt, profile prose, portfolio path/label, ID, email, message, verification/dispute document or purchase token reaches the provider. No provider network key or paid service is configured. Future live provider activation requires separate privacy, retention/deletion, spend and schema review.

M5.4 adds transient editable booking-brief suggestions, creator-owned profile improvement tips and public shortlist comparisons. These routes never book, message, edit a profile or pay. The Expo Router Lavender screens require authentication, clear actor-scoped drafts on account switch, discard late results after constraint changes/cancellation, and show empty/loading/error states. Text and comparisons stay in component memory; no automatic server or device persistence is introduced.

All four rollout flags default false. Phase 3 booking, messages, history and discovery remain available without calling Phase 5 routes; there are no Phase 4 schema references. An eventual Phase 4 integration needs a separate reviewed compatibility PR, especially around moderation/visibility and trust signals. This branch makes no claim that Phase 4 is approved.
