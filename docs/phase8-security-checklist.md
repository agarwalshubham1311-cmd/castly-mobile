# Security validation and gates

M7.1: verified JWT boundary retained; TOTP AAL2 + short admin session; trusted AMR timestamps; no self/super promotion; fixed permissions; same-origin JSON BFF; HttpOnly Strict cookies; nonce CSP/frame denial; fixed proxy routes/origins; bounded bodies/responses; no redirects; least-privilege RLS; transactional append-only audit; actor quotas. Test evidence/results and npm dependency scan findings are recorded in phase7-milestones.md. No production security certification is claimed.

Before exposure: independently review IDOR/BOLA, role/MFA/session fixation/revocation, JWT issuer/audience/algorithm/expiry, RLS recursion and app-role isolation, input SQL/XSS/CSRF/SSRF/upload bounds, unsafe links/logging and account erasure. Integrated Phase4 trust and Phase6 notifications must be included when testing fraud/reports/spam/replay/entitlement abuse across the actual hosted deployment tree. No unnecessary identity documents may reach support agents.

BFF process-local 30/min auth throttle is only supplemental. Require provider/edge per-IP/account limits and brute-force/credential-stuffing controls before rollout. Do not trust arbitrary X-Forwarded-For. Audit stores HMAC of the actual backend TCP peer (the BFF in proxy mode), plus a reduced untrusted browser family, not an asserted end-user IP. Configure a validated trusted-proxy boundary before changing that provenance. Review IP-key retention, reason entry policy and audit retention with privacy owners. No independent immutable audit sink has been activated. Privileged DB owners remain able to alter schema; application append-only controls cannot prevent that.

M8.2 tools: npm audit, Maven dependency/OWASP feed scan, secret scanning, Semgrep and container Trivy in isolated CI; retain JSON/SARIF artifacts, severity/CVE/version/fix/owner/expiry. Do not upload secrets to scanners or silently apply breaking upgrades. No unresolved critical vulnerability may pass launch; high findings require remediation or explicit signed risk acceptance. npm audit alone is not a complete scan or penetration test. Pin/review action versions and configure Dependabot in that milestone. No production attack/load test is authorized.
