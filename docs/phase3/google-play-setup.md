# Google Play setup and operator guide

No Google products, credentials, Play testing or live billing were configured by this implementation. All activation flags default false. The [compatibility evidence](google-play-compatibility.md) distinguishes package-source inspection from official documentation and native-device validation.

1. Confirm ownership of the exact Android application ID used by the APK workstream. Keep `CASTLY_ANDROID_PACKAGE` aligned with backend `GOOGLE_PLAY_PACKAGE_NAME`. Do not create a competing EAS project/package.
2. Review current official Google Play Billing requirements and build the Expo 58/RN 0.88 integration in an approved custom development or Play testing build. Installed source: expo-iap 6.4.3 (Expo Module), OpenIAP Google 4.0.10; package README reports Billing 9.1.0. No native build was initiated here. Expo Go does not load the billing module.
3. In Play Console, create the approved Creator Pro subscription/base plan and optional offers. Product prices, currencies, tax and offer eligibility belong in Play Console; no price is invented in Castly. The mobile adapter displays Play-returned pricing phases and passes the eligible offer token. V1 exposes one configured Creator Pro product/base plan; native product replacement support and linked-token reconciliation are implemented, but no multi-tier upgrade selector is offered until a reviewed catalog establishes multiple tiers.
4. Enable the Android Publisher API and grant a dedicated backend service account the minimum Play Console app-specific subscription/order management permissions needed for subscriptionsv2 reads and acknowledgement. Store its JSON in a backend-mounted secret file. Set `GOOGLE_PLAY_CREDENTIALS_FILE`; never place its content/path/key in Expo public variables. Verify IAM permissions against a license-test purchase before enabling checkout.
5. Generate and securely back up a stable `GOOGLE_PLAY_ACCOUNT_KEY` with at least 32 random characters. HMAC-SHA256 of Castly UUID produces Google's obfuscated account ID. Rotating this key changes identity binding and can prevent existing purchases from restoring; plan/version/migrate mappings before rotation. No key is generated or provisioned by this task.
6. After separately approved schema review, configure `subscription_plans.google_product_id` and `google_base_plan_id` on the Creator Pro row through the database owner's reviewed workflow. Castly API cannot edit catalog or provision reviewers. Free/Pro portfolio limits default NULL to preserve current unlimited behavior; review rollout/grandfathering before setting finite values and ensure Pro's limit is larger. Future server premium feature names may be configured in `premium_features`; no future feature is implicitly enabled.
7. Create a Pub/Sub topic and grant Google Play's notification publisher identity permission to publish, per current official guidance. Configure Play RTDN for this topic. Create an authenticated HTTPS push subscription to `/api/v1/subscriptions/google-play/rtdn`, with a dedicated push service account. Set exact `GOOGLE_RTDN_AUDIENCE` and `GOOGLE_RTDN_SERVICE_ACCOUNT_EMAIL`; allow Google's Pub/Sub service agent to mint that identity token. Use Google issuer `https://accounts.google.com`. Test valid/invalid audience, identity, duplicate message delivery, retry after API outage and dead-letter monitoring. `deliveryAttempt`, message `orderingKey`, attributes and publishTime are accepted. RTDN is independent of disabled Castly in-app notifications.
8. On approved staging only, enable `CASTLY_SUBSCRIPTIONS_ENABLED=true`; leave `CASTLY_NOTIFICATIONS_ENABLED=false`. Enable `CASTLY_GOOGLE_PLAY_ENABLED=true` for provider verification/RTDN only after package/product/IAM/RTDN setup. Keep `CASTLY_GOOGLE_PLAY_CHECKOUT_ENABLED=false` until checkout is separately approved; it can stop new checkout without stopping restore or RTDN. Build-time `EXPO_PUBLIC_GOOGLE_PLAY_BILLING_ENABLED=true` enables the native adapter/plugin; it remains gated by backend configuration and actual product query results. Native module absence, Expo Go, web, unset products or invalid credential file keep checkout unavailable.
9. Run Play license testing: product offers and renewal terms, purchased/pending/cancelled, ack within Google's required window, grace/hold/resume, cancellation until expiry, expiration, refund/revoke, restore on same/different Castly accounts, duplicate callbacks, network interruption, app restart and replacements. Capture redacted evidence. Only then consider an explicitly approved production activation.

## Manual founding-offer review

The owner provisions exact reviewer user UUIDs into `private.subscription_admins` after approval. Sign in normally, then open `/subscriptions/review`. The queue identifies creator UUID and public post URL. Confirm the post belongs to that creator and qualifies, enter a reason/evidence, and approve or reject. Approval grants 12 calendar months atomically; repeat approvals return the existing decision. Reviewers cannot self-review. One claim per creator is intentional in v1; rejected claims are retained rather than overwritten. Appeals/resubmission require a separately reviewed policy and workflow.

## Failure recovery

A mobile callback is not payment proof. If verification fails, show the failure and use Refresh/Restore; never manually fabricate a paid grant. Google API outage responses are sanitized 503. Normal RTDN receipts roll back on failure so Pub/Sub retries. Trusted revoke events terminate the associated paid grant without revoking overlapping promotional access. Store tokens only travel transiently from native billing/RTDN to Spring over authenticated HTTPS. There is no stored-token polling worker; monitor Pub/Sub and use Restore for reconciliation. Do not log request bodies/Authorization headers at the reverse proxy.
