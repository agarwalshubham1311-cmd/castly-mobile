# Catalog and entitlements

All responses use snake_case. Membership routes require a verified Supabase JWT except GET `/api/v1/subscriptions/plans`. GET `/subscriptions/me` resolves active ledger grants at database time and returns plan, features and expiry; GET `/subscriptions/history?limit=25&offset=0` returns only the caller's orders, without purchase identifiers/tokens. Limits are 1–100, offsets 0–10000. Existing `/account/entitlements` resolves effective grants when the module is enabled.

`CASTLY_SUBSCRIPTIONS_ENABLED=false` is the deployment default. Enable only after reviewed migration application. Free bookings/messaging stay available. Catalog entries have no invented prices or configured Google products. Portfolio limits seed as NULL (existing unlimited behavior); operators must approve finite limits and a Pro increase before advertising numerical limits. The Spring portfolio creation transaction enforces configured limits under a per-account lock, without deleting preexisting assets. Premium discovery eligibility is a server-derived membership feature, not a client-writable profile field; published discovery responses expose `premium_discovery_eligible` from the server projection; merchandising/ranking is not automatically changed.

Legacy entitlements are imported once at schema cutover, including unknown entitlement names and perpetual grants. The grant ledger becomes authoritative after activation; `subscription_entitlements` remains a compatibility projection. Post-cutover manual adjustments must update the ledger and projection in one reviewed owner transaction. Do not continue writing the old table as an independent authority.
